# BiliDownOut v1.6.1 宣发与苹果风落地页计划

## 一、Summary

项目已达稳定发版状态（v1.6.1，master 干净历史、CI 绿、Release 已发布）。本文档为「宣发」做决策完备的计划，回答三个问题：

1. **哪些平台、各自什么风格**（务实 vs 夸张）
2. **文章逻辑与数量**（保证用户爱读、爱看）
3. **能不能用网页做苹果式产品宣传动画**（能，且本次把它作为宣发主力落地页）

核心结论：
- **受众分成两条线**：B站普通下载用户 + 技术/开发者社区，用**不同文章**打。
- **整体基调以「务实」为主**，仅在视觉种草平台（小红书封面、B站封面）适度夸张；语言诚实克制（与项目 AGENTS/MOTIVATION 一贯的谦逊调性一致），因为工具类产品的信任感来自"不说大话 + 直接给可下载的东西"。
- **苹果风滚动叙事落地页是本次的「内容母版」**：一篇滚动驱动的 web 落地页承载全部价值点，各平台文章都从它派生/引用，降低重复写作成本、形成统一记忆点。
- **建议产出：1 落地页 + 2 篇核心原创（用户向/开发向）+ 5 篇平台适配改稿**。

## 二、Current State Analysis（现状）

可直接复用的素材与事实：
- **产品定位**：把哔哩哔哩 APP 离线缓存（`Android/data/tv.danmaku.bili/download/` 深处的 entry.json + 分片）干净导出为 MP4，按 UP 主归档。
- **核心功能**（见 [README.md](../../README.md)、[docs/MOTIVATION.md](../../docs/MOTIVATION.md)）：
  - 按 UP 主分组浏览（中文拼音排序 + 头像）
  - 番剧/影视独立分组（不再混入"未知 UP 主"）
  - 多维排序（UP 主拼音 / 名称 / 大小）
  - 导出记录多选 + 批量操作
  - 列表缓存持久化（进程被杀后首开不转圈）
  - Shizuku 免 root 访问 Android/data
  - 现有截图 3 张：`fastlane/metadata/android/zh-CN/images/phoneScreenshots/{1,2,3}.jpg`
- **发布渠道（现成）**：GitHub Releases v1.6.1（`BiliDownOut-1.6.1-debug.apk`，debug 包）。
- **上游关系**：fork 自 `10miaomiao/bili-down-out`，须保持谦逊归功上游。

> 关键判断：这是一个**非官方、工具向、已能稳定发版**的个人开源增强分支。过度营销会引来反噬；「务实 + 诚实的痛点 + 直观演示」是最优解。

## 三、平台矩阵与风格

| 平台 | 受众 | 风格取向 | 形态 | 侧重点 / 打法 |
| --- | --- | --- | --- | --- |

| **哔哩哔哩** | 视频用户 / 泛泛 | **务实 · 演示向** | 短演示视频 + 专栏 | 演示"导出 3 步"流程最有说服力；封面允许情绪化标题，正文讲步骤。 |
| **掘金 Juejin** | 技术 / 开发者 | **务实 · 技术长文** | 长文技术帖 | 讲架构、分组排序实现、AI 阅读路线（复用 `docs/IMPLEMENTATION.md`）。 |
| **V2EX** | 技术社区 | **低调务实 · 谦逊帖** | 简短讨论帖 | 讲动机、功能、求 star；语气诚实、不吹嘘，回应"和上游区别"。 |

**风格总原则**：
- 技术/工具向（酷安、掘金、V2EX、B站正片）：**完全务实**，主打可靠性、上手、对比。
- 泛消费/种草向（小红书、B站封面）：**克制地夸张**——钩子可以抓眼球，但正文不造假、不夸大性能。
- 所有平台统一**诚实声明**与上游关系，引导到 GitHub/酷安下载，形成倒流闭环。

## 四、苹果风宣传动画落地页（技术方案）

**结论：完全可行。** 苹果产品页的核心是"滚动驱动叙事"：文字随滚动放大/淡出、功能模块逐段滑入、产品 mockup 视差。用纯 web（单 HTML 自包含）即可实现，无需重型框架。

### 技术选型
- **单文件自包含 HTML**：`docs/promo/index.html`（内联 CSS/JS，零依赖，双击即开、可部署、可分享）。
- **滚动驱动动画双保险**：
  - 优先用 **IntersectionObserver** + CSS transform/opacity 过渡实现逐段揭示（兼容性最好）；
  - 对照 **CSS Scroll-Driven Animations**（`animation-timeline: view()`/`scroll()`）做增强，不支持的环境自动降级为 IntersectionObserver。
- **视觉构成**：
  - Hero：大标题滚动放大 + 淡出（"酒香也怕巷子深"式的开场感）。
  - 3 个功能大节点（按 UP 主分组 / 番剧独立 / 多维排序）逐个滚动滑入。
  - 手机 mockup：用真实截图 `1.jpg/2.jpg/3.jpg` 做成设备框，随滚动做轻微视差/浮起。
  - 底部 CTA：GitHub Release 链接 + Star 引导。
- 默认**不用**占位图，一律使用真实截图与真实文案（符合项目"内容即上下文"的诚实调性）。

### 落地页的定位
作为**宣发母版 / 中心入口**：
- 覆盖"用户向"完整信息（是什么→怎么用→怎么下载）。
- 各平台文章从落地页的章节标题、截图、话术直接派生，避免每篇重新写。
- 落地页自身可作为"备用内容"（例如分享链接到各平台，供想看完整版的人点进来）。

## 五、文章逻辑（内容母版：7 段式）

每篇（无论方向）都套同一骨架，保证用户爱读、节奏好：

1. **痛点钩子**（前 5 秒抓住）："B站缓存的视频在 Android/data 深处，文件管理器导不出来"——用具体场景而非抽象功能。
2. **一句话价值主张**：把哔哩哔哩离线缓存干净导出成 MP4，按 UP 主归档。
3. **是什么**：一句话定位 + 一句与上游的关系。
4. **场景化功能演示**（不是功能列表）：每条配一张真截图/动图——"找某 UP 的缓存→点开→勾选→导出"。
5. **上手 / 安装**：下载位置 + Shizuku（Android 13+）说明。
6. **与上游关系 + 开源谦逊 + 求 star**：归功上游、说明这是增强分支。
7. **CTA**：明确了下载地址与反馈入口。

**保证"喜欢读"的细节**：每段一个核心点、多用截图代替文字、诚实不吹嘘、场景优先于参数、CTA 明确。

## 六、文章数量与首发节奏

**建议产出总数：1 落地页 + 2 篇核心原创 + 5 篇平台改稿。**

- **核心原创 2 篇**（决定内容的天花板）：
  1. `docs/promo/article-users.md` —— 用户向母稿（务实，覆盖 7 段式全流程）。
  2. `docs/promo/article-devs.md` —— 开发向母稿（技术深度，复用 IMPLEMENTATION）。
- **平台改稿 5 篇**：酷安、B站（专栏/演示脚本）、掘金、V2EX、小红书——各 1 篇，由母稿裁剪/改语气，而非重写。
- **落地页 1 个**：`docs/promo/index.html`（苹果风动画）。

**首发节奏（建议）**：
1. 先发落地页（自测 + 内部分享）。
2. 酷安发版帖（最精准、能立刻拿到目标用户）。
3. B站演示视频 + 掘金技术文（扩大影响面）。
4. V2EX 谦逊帖（技术圈口碑）。
5. 小红书（泛人群拉量，最后放，避免主次颠倒）。

## 八、Assumptions & Decisions（假设与决策）

- **受众分两线**：普通用户线（酷安/B站/小红书）+ 开发者线（掘金/V2EX），各自独立成稿（用户已确认）。
- **苹果风落地页本次就做**，定位为宣发主力 + 母版（用户已确认）。
- **整体务实为主、种草处适度夸张**：视觉钩子可抓眼球，内容不造假。理由：工具类信任 = 诚实 + 可直接用。
- **debug 包变化**：带 `versionName 1.6.1`；若宣发期间有新版，只需更新版本号与链接，结构不变。
- **不做付费投放 / 不做夸大隐私或性能承诺**（提升可信度，避免反噬）。
- 落地页与文章为**新增文档/静态资源**，不触及 Android 源码逻辑。

## 九、Verification（验证步骤）

1. **落地页**：打开 `docs/promo/index.html`，核对滚动时各段落动画正常、无控制台报错、真实截图正确显示、CTA 链接可达 GitHub Release。
2. **文章**：逐篇对照 7 段式骨架核对其完整性；核对下载链接、Shizuku 说明、与上游关系表述一致且诚实。
3. **一致性**：所有平台帖子的"下载地址 / 版本号 / 功能点 / 与上游关系"四要素与落地页、README 一致，避免多平台信息互相矛盾。
4. **可分享性**：落地页可通过 `python3 -m http.server` 或静态托管预览；便于复制到各平台做"完整版"入口。
